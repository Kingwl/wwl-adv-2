# 设计：MVP 五关波次节奏

## 状态

Accepted

## 当前实现状态

截至 2026-05-11，五个 MVP 关卡的第一版数据已落地：

- 关卡文件为 `game/data/levels/level_001.json` 到 `level_005.json`。
- 每个关卡通过 `wave_set_id` 引用 `game/data/waves/<wave_set_id>.json`。
- `game/data/waves/waves.json` 保留为默认兼容入口，并使用 Training Gate 的 8 波节奏。
- `level_001` 使用现有 `stormwind_city_v3` baked 地图；`level_002` 到 `level_005` 已接入 Long Road、Kill Zone、Armored Column 和 MVP Showcase 的 baked map style，并使用差异化 `path_cells`。
- 长局 balance summary / gameplay smoke 仍待补。

## 背景

当前 playable prototype 已经有放塔、升级、拆除、战斗、奖励、漏怪、胜负和三波全局 `waves.json`。MVP 需要从“能通一小局”推进到“能展示更长的一组关卡”，但现在仍只有三类基础敌人：

| 敌人 | 速度 | 生命 | 击杀奖励 | 当前定位 |
| --- | ---: | ---: | ---: | --- |
| `grunt` | 1.0 | 20 | 5g | 基础密度单位 |
| `bruiser` | 1.0 | 24 | 5g | 稍厚单位 |
| `raider` | 1.1 | 30 | 6g | 更快且更贵的压力单位 |

因此 MVP 第一版波次节奏不引入混合波、Boss、随机刷怪或特殊路线；它先用每关 8 个单敌种波次建立可实现、可测试、可调参的基线。后续增加敌人变体时，可以替换部分 wave 的 `enemy_type`，而不改变每关的压力曲线。

## 目标

- 定义 5 个 MVP 关卡的第一版 8 波节奏。
- 让每关有清晰的教学或压力主题，而不是简单递增数字。
- 给出每波敌人、数量、间隔和清波奖励，便于直接落入数据文件。
- 保持波次确定性：静态 JSON、固定 tick、无运行时随机选择。
- 明确实现前需要补的 level-specific wave set 数据契约和测试入口。

## 非目标

- 不在本文档中承诺最终数值平衡；这些表是第一版调参基线。
- 不设计 Boss、精英词缀、多路线、分裂刷怪或随机刷怪。
- 不扩展新敌人类型；现有三类敌人不足以表达的差异先用数量、间隔和奖励表达。
- 不改变当前胜负条件和奖励服务语义。

## 方案

### 节奏原则

- 每个 MVP 关卡固定 8 波，满足长局演示和自动化 smoke 的最小内容量。
- 每波只生成一种敌人，兼容当前 `WaveDefinition` 形状。
- 前两波建立经济和放置空间；第 3 波引入关卡主题；第 5 波制造一次节奏变化；第 8 波作为最终检查。
- 清波奖励作为节奏工具：第 4、6、8 波奖励更高，给玩家在压力波后升级或补塔。
- `spawn_interval_seconds` 控制瞬时密度，`enemy_count` 控制持续压力，`enemy_type` 控制目标优先级。
- 表内总金币只计算潜在击杀奖励和清波奖励，不含初始金币 100g，也不假设所有敌人都会被击杀。

### 数据契约

短期实现应从单一全局 `game/data/waves/waves.json` 扩展为关卡引用 wave set：

```json
{
  "id": "level_001",
  "display_name": "Training Gate",
  "wave_set_id": "level_001_training_gate"
}
```

推荐继续使用现有 waves 目录，新增 `game/data/waves/<wave_set_id>.json`。`waves.json` 可以暂时保留为默认关卡兼容入口，但新关卡应显式声明 `wave_set_id`。

实现时需要同步：

- `level.schema.json` 增加 `wave_set_id`。
- `LevelDefinition` 读取并暴露 `wave_set_id`。
- `WaveConfig` 支持按 level 或 wave set id 加载。
- `check-assets.py` 校验每个关卡引用的 wave set 存在、每个 wave 引用有效敌人、MVP wave set 恰好 8 波。
- GUT 覆盖默认兼容加载、按关卡加载、缺失 wave set、无效敌人引用和 8 波 MVP fixture。

## 替代方案

- 继续扩展单一 `waves.json`。放弃原因是无法让不同关卡拥有不同节奏，也会让未来多地图测试和 smoke 选择变得含糊。
- 先实现混合波。放弃原因是会改变 `WaveDefinition` 数据形状、刷怪器和测试矩阵；MVP 第一版用相邻单敌种波已经足够建立节奏。
- 先新增敌人再做五关。放弃原因是 MVP 当前更缺长局内容和验证入口；敌人变体可以后续替换 wave slot。
- 用随机波次或动态预算生成。放弃原因是当前项目优先确定性模拟和可复现测试，随机内容不适合作为 MVP 基线。

## 风险

- 三类敌人差异较小，Level 4 和 Level 5 的主题表达会受限。
- 表内奖励是按当前塔成本和敌人奖励估算的第一版，不代表已经可通关。
- 如果 8 波都自动连续推进，玩家可能没有足够操作时间；实现后需要观察是否加入波间暂停或手动开波。
- 多 wave set 会扩大资产/schema 检查范围，必须在实现时把失败信息做清楚，否则调内容会变慢。

## 决定和开放问题

- 已决定：`wave_set_id` 显式写在 level 中。
- 已决定：MVP 第一版清波奖励继续放在每个 wave 中。
- 开放：是否需要 `delay_before_next_wave_seconds` 或手动开波？本文不作为 MVP 第一版前置条件。
- 开放：Level 4/5 是否应在后续新增抗性或高血敌人？当前先用现有三敌人落地，再替换敌人 id。
