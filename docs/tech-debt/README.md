# 技术债

这个目录用于跟踪已知技术债、清理计划和工程风险。

## 建议文件

- `register.md`：集中式技术债登记表。
- `YYYY-MM-DD-topic.md`：特定技术债条目的详细说明。

## 期望

每个技术债条目应包含影响、受影响区域、建议修复方式、优先级，以及已知负责人。

## 生命周期

- `Open`：风险仍存在，且会影响维护成本、正确性、测试信心、性能或交付节奏。
- `Mitigated`：风险已经被结构性降低，例如拆分职责、增加门禁或迁移配置，但仍需要继续观察。
- `Closed`：风险已经不存在，或已经被测试、门禁、架构边界或流程稳定覆盖。

## 更新规则

- 新增技术债时，写清楚风险区域、影响、优先级、状态和偿还触发条件。
- 缓解或关闭技术债时，更新 `register.md` 中的状态和备注。
- 普通待办、试玩反馈、视觉问题和短期后续项放到 `../todo/backlog.md`，不要放进技术债登记表。
- 当前状态、最近验证和下一步优先级放到 `../status.md`，不要在技术债目录重复维护。
